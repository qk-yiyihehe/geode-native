# 母岩跨进程断点续跑

2026-10-25 实现，断点格式 `geode-v1`。本次只构建和测试原生源码，没有打包或更新 `desktop/dist/` 中的发行程序。

## 使用与位置

CLI 默认启用，断点放在 `--output` 目录下的 `checkpoints/`。再次执行相同计算参数会自动恢复，无需额外 resume 命令。

```powershell
.\build\geode-finder.exe --seed 12345 --version 26.3 --radius 100000 --prefilter-limit 200000 --output results
# 自定义位置；断电或进程被结束后，原样执行此命令。
.\build\geode-finder.exe --seed 12345 --version 26.3 --radius 100000 --prefilter-limit 200000 --checkpoint-dir "results/断点 缓存"
# 完全关闭断点读写，也不清理之前的断点。
.\build\geode-finder.exe --seed 12345 --radius 10000 --no-checkpoint
```

配置文件可以设置 `geode-checkpoint-directory`；CLI 的 `--checkpoint-dir` 优先，`--no-checkpoint` 优先于两者。单点、单洞和 samples 查询不创建断点。

桌面协议入口自动使用进程工作目录下的 `config/checkpoints/geode-native/`，与现有试炼约定一致。单文件启动器/壳选定的应用根目录决定实际位置；断点不放在 exe 构建目录，也不另设固定 C/D 盘路径。使用新构建的引擎时，提交相同搜索配置即可恢复，`resume` 命令仍表示进程内解除暂停。

文件名为 `geode-v1-<参数指纹>.bin`。成功生成结果后自动删除对应文件；取消、强杀或导出失败保留已提交记录。桌面延迟导出模式在完整结果和三种导出内容准备成功后清理，不要求用户先另存为。清空某个旧任务时，在该任务未运行的情况下删除其 `.bin` 文件即可；其他参数的断点不会被自动删除。

## 保存与恢复

| 阶段 | 提交单位 | 保存内容 |
|---|---|---|
| CPU粗筛 | 512×512区块瓦片，边缘按实际范围裁切 | 完成编号、覆盖计数及正确/历史双阈值全局候选池的入池增量 |
| GPU粗筛 | 原有4096区块边长批次，完成回传后提交 | 同上；重启重建OpenCL上下文，跳过已提交批次 |
| 粗筛结束 | 完整阶段 | 排序去重后的候选集合、实际设备和统计；完整候选模式也保存此阶段 |
| 局部模拟 | 既有64×64来源区块空间分区 | 母岩区块权重增量、存在晶洞来源、模拟及否决计数、工作分区标识 |
| 热点排名 | 从恢复后的完整候选和权重重算 | 不只保存前100，不改变热点分组、几何优化与最终排序 |

每条记录包含长度、完整数据和校验值，计算数据与完成标记一起提交。重启顺序回放，再截掉未写完的尾部。半写头部可重建，已完整写出但校验不符的记录会报错，不能默默跳过。相同参数的断点由操作系统排他控制，拒绝两个进程同时修改。

各线程粗筛可以用恢复的全局池初始化安全阈值，但最终只合并一次全局候选池，避免多个线程重复携带历史候选挤占容量。模拟按来源分区累计，邻区块中的母岩权重可以正常相加，同一已提交分区不会重复计算。

不序列化地形、结构、噪声缓存或GPU状态。日志只追加已提交的候选变化和分区结果，不在逐母岩循环写盘。约每秒在新记录提交时请求系统刷盘，正常关闭也刷盘；物理断电可能需要重算未刷盘的后缀和正在计算的分区，不保证只丢失固定一秒工作。

## 兼容与计时

- 指纹包含种子数值、版本/生成代际、模型及工作划分修订、范围/形状、活动规则、阈值、候选预算、Top K、线程数、请求设备和排名规则。
- 参数改变时使用另一份断点，不复用旧任务；文件头也保存完整指纹，不能靠重命名强行复用。
- 当前要求线程数、设备配置一致。auto任务若已部分使用GPU，恢复需要兼容GPU；不能把旧GPU批次编号当成CPU瓦片编号。已经完成粗筛的任务直接恢复候选，无需重新启动GPU。
- 修改生成算法、热点语义或工作划分时，须更新 `SearchCheckpoint` 的模型/工作修订或升级格式；不可只靠同一版本号复用旧数据。本格式用于当前原生构建平台，不承诺任意架构间通用。
- `timing.resumedMs` 是恢复的已提交历史有效耗时；`searchMs` 为该历史加本次有效搜索时间，`pausedMs` 为本次进程暂停，`totalMs` 为加历史后的任务墙钟至结果准备完成。进程关闭到重启的间隔不计入。
- `stats.resumedCoarseUnits`、`stats.resumedSimulationUnits` 表示本次跳过的历史工作单位，`simulatedGeodes` 等仍为整个任务累计统计，不是本次新增量。
- 两段式裁剪只适用于地形模型下"有限预算 + 1.21.5 起方形活动规则"的任务。它改变了模拟阶段的工作划分，所以工作修订已升级为 `work=512-4096-64-twopass`，与升级前的断点不混用。裁剪启用时 `simulatedGeodes` 只统计地形那一遍，上界那一遍计入 `stats.stoneGeodes`；断点恢复的百分数按合并后的总量计算。

本功能保证延续已有模型与候选预算，不提高真实世界精度，也不把有限候选变成真实前100证明。

## 验证

以下回归仅适用于保留本地`tests/`及Python的开发环境，测试文件不随仓库提交。入口为`build.ps1 -Test`，包含`checkpoint`测试。可选GPU扩展：

```powershell
python tests/checkpoint.py build/geode-finder.exe --gpu
```

本机Windows构建常规CTest已通过11/11；可选GPU扩展也已通过，包含真实GPU粗筛进程强杀后的批次恢复。未新增大范围I/O性能结论。

另有真实子进程强杀恢复、部分头部/尾部、损坏校验、参数隔离、重命名错误指纹、并发写入拒绝、桌面跨进程重启、恢复后的暂停计时、延迟导出和成功清理检查。强杀测试不等于物理断电实验。
